# sprite_stack

Render **sprite-stacking** props in Flutter with free turntable rotation.

A sprite stack is a set of horizontal cross-sections of a 3D shape. Drawing
them bottom-up, each one rotated and vertically squashed, produces a fake-3D
billboard you can spin in any direction — the same trick used by pixel-art
games since the 90s, with one `drawImageRect` per slice and no 3D pipeline.

```
slices (ground slice on the left)
┌────┬────┬────┬────┬────┐
│ 0  │ 1  │ 2  │ …  │ 23 │   each slice: top-down cross-section
└────┴────┴────┴────┴────┘
        ↓ render bottom-up
      ╱▔▔╲        yaw   → rotation around the vertical axis
     │    │       pitch → camera tilt (0 = edge-on, π/2 = top-down)
      ╲__╱        spacing → lift between slices
```

## Asset format

- One **horizontal strip** PNG, all slices the same size.
- **Ground slice first** (left), last slice on the right.
- `sliceCount` is required at load time — the strip carries no metadata
  (`sliceWidth = imageWidth / sliceCount`).

The strip is produced from four orthographic views (top, side, front, back) by
[danielwh2/sprite-stacking](https://github.com/danielwh2/sprite-stacking) (MIT):

```bash
python3 skills/sprite-stacking/scripts/views_to_slices.py views.png slices.png \
  --slices 24
```

## Usage

```dart
final stack = await SpriteStack.load('assets/robot_stack.png', sliceCount: 24);

// Plain Flutter: bottom-center anchor, any canvas.
class PropPainter extends CustomPainter {
  @override
  void paint(Canvas canvas, Size size) {
    stack.render(
      canvas,
      position: Offset(size.width / 2, size.height),
      yaw: 0.6,
      pitch: 0.55,
      scale: 6,
    );
  }

  @override
  bool shouldRepaint(covariant CustomPainter oldDelegate) => true;
}
```

Or use the included painter:

```dart
CustomPaint(
  size: const Size(320, 320),
  painter: SpriteStackPainter(stack: stack, yaw: yaw, pitch: pitch, scale: 6),
)
```

### Flame / Bonfire

```dart
add(
  SpriteStackComponent(
    stack: stack,
    position: Vector2(120, 200),
    yaw: 0.6,
    stackScale: 4,
    priority: 10, // Y-sort with the rest of the scene
  ),
);
```

`SpriteStackComponent` keeps `size` in sync so hit boxes and `priority`-based
sorting work as usual. `yaw` spins the prop; it does not touch the component's
own `angle`.

## API

| Member | Meaning |
| --- | --- |
| `SpriteStack.load(path, sliceCount:)` | Loads a strip from a Flutter asset |
| `SpriteStack.decode(bytes, sliceCount:)` | Decodes a strip from memory |
| `SpriteStack.fromImage(image, sliceCount:)` | Wraps an already decoded `ui.Image` |
| `render(canvas, position:, yaw:, pitch:, scale:, spacing:, paint:)` | Draws the stack |
| `sliceWidth`, `sliceHeight`, `sliceSize`, `sliceCount` | Strip geometry |
| `heightFor(pitch:, spacing:)` | Rendered height in source pixels |
| `SpriteStack.defaultPitch` | `0.55` rad (~31°) |
| `dispose()` | Releases the decoded image |

`pitch` is clamped to `0..π/2` and its squash to `0.08..1`, so the stack never
collapses to nothing.

## Performance

- One `drawImageRect` per slice, in a single decoded texture.
- 24 slices ≈ 24 draws per prop. A hundred props is ~2.4k draws — fine for
  Flame, but if a scene gets heavy, bake 16 directions ahead of time and use a
  normal sprite sheet instead.
- Cache the `SpriteStack` (and therefore the `ui.Image`) per asset, not per
  instance.

## Limitations

- Painter's algorithm: props that intersect each other cannot resolve per voxel.
- No per-voxel lighting, shadows or reflections. Shading has to be baked into
  the slices (the generator already darkens side faces).
- The strip must have uniform slices; `sliceCount` must match the asset.
